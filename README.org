* org-natural-dates

Natural language date parsing for Org mode scheduling, deadlines, and capture.

Type what you mean — =tomorrow at 3pm=, =every Friday=, =in 3 days= — and let Org figure out the timestamp.

** Examples

| You type                              | Org result                               |
|---------------------------------------+------------------------------------------|
| =tomorrow=                            | =SCHEDULED: <2026-02-22 Sun>=            |
| =next Tuesday at 10am=                | =SCHEDULED: <2026-02-24 Tue 10:00>=      |
| =in 3 days=                           | =SCHEDULED: <2026-02-24 Tue>=            |
| =every Friday=                        | =SCHEDULED: <2026-02-27 Fri +1w>=        |
| =every 2 weeks=                       | =SCHEDULED: <2026-02-21 Sat +2w>=        |
| =every day at 5pm=                    | =SCHEDULED: <2026-02-21 Sat 17:00 +1d>=  |
| =due tomorrow= (in capture)           | =DEADLINE: <2026-02-22 Sun>=             |

Works with =org-schedule=, =org-deadline=, Org Agenda, and =org-capture=.

** Optional local Duckling backend

The fork's ~org-natural-dates-duckling-mode~ replaces text interpretation in
Org's existing calendar prompt.  This covers ~C-c .~, ~C-c !~, scheduling,
deadlines, and packages such as org-timegrid that call ~org-read-date~.  Calendar
navigation and event decorations continue to use Org's UI.  Standalone Calendar
and unrelated date readers are not changed.

Download the helper once with ~M-x org-natural-dates-duckling-install~.
It runs curl in the background and returns immediately, with progress in
~*org-natural-dates-install*~.  Wait for the completion message before first
use.  ~M-x org-natural-dates-duckling-cancel-install~ cancels a download.
Installation is never started from the date prompt or package activation.
The package does not bundle a binary in Git or its Elisp build directory.
The installer selects a pinned GitHub release for the current platform,
verifies SHA-256, and installs it under ~user-emacs-directory/org-natural-dates/~.
An existing installation is reused; a prefix argument forces a new download.
Only installation requires curl/network access.  There is no Rust, Docker,
server, model, or network connection during parsing.

#+begin_src emacs-lisp
(require 'org-natural-dates-duckling)
;; Optional: put downloaded binaries in your cache instead.
(setq org-natural-dates-duckling-directory
      (expand-file-name "cache/org-natural-dates/" user-emacs-directory))
(org-natural-dates-duckling-mode 1)
(add-hook 'org-capture-before-finalize-hook #'org-natural-dates-capture-finalize-hook)
#+end_src

Downloads support macOS ARM64/Intel, Linux ARM64/x86-64 (glibc 2.35+), and
Windows x86-64.  macOS binaries require macOS 11+.  Missing downloads produce
an actionable install error; they are not fetched while typing a date.
Customizing the directory changes the managed path automatically.  The optional
~org-natural-dates-duckling-program~ overrides it with a separately installed
executable.  Failed downloads/checksums leave the current executable untouched.

Developers can still build from source:

#+begin_src sh
make helper
make check
#+end_src

The test suite uses that locally built binary, or the path in the
~ORG_NATURAL_DATES_DUCKLING_PROGRAM~ environment variable.  Release binaries
are built by the ~duckling-v*~ tag workflow; the Cargo source and lockfile
remain in this repository.

The original Elisp parser remains the default unless this mode is enabled.
~org-natural-dates-parser-function~ can select a task parser independently.

| Input                     | Result                                      |
| ~tomorrow at 8pm~          | Tomorrow, 20:00                             |
| ~19th next month at 20:00~ | The 19th of next month, 20:00                |
| ~+2d~, ~+2~, ~+1w~, ~-2d~ | Offsets from today                          |
| ~+2h~                     | Two hours from now                          |
| ~++2d~, ~--1w~            | Offsets from the date being edited          |
| ~.~                       | Today                                       |

Shorthand is translated to full unit names before Duckling parses it.  Blank
input accepts the default/selected date.  Clock-only edits keep the selected
day.  Unsupported text raises an error, with no automatic fallback to Org's
permissive text parser.  RET validates while the minibuffer remains open so
invalid expressions can be corrected.

Capture extracts the title and adds a schedule, for example:

#+begin_example
* TODO Family dinner on 19th next month at 8pm
#+end_example

becomes ~* TODO Family dinner~ with the corresponding ~SCHEDULED:~ timestamp.
~due~, ~by~, and ~deadline~ select ~DEADLINE:~.  Ordinary captures, including
~Read chapter 8~, remain unchanged.  Meal titles such as ~Lunch~ are retained.

Capture recurrence reuses the existing Org repeater parser, including ~every
day~, ~every Friday~, ~every 2 weeks~, and ~every other month~.  The shared
calendar prompt rejects recurrence because ~org-read-date~ returns a date, not
a repeater; use natural-language capture or this package's scheduling wrappers
for those expressions.  Existing repeaters survive timestamp edits.

Current limits of Rust Duckling 0.4.0:

- Bare hours such as ~at 8~ require AM/PM.
- Ranges and before/after constraints are rejected rather than approximated.
- Slash dates require ISO syntax or a month name because the port ignores UK
  ordering for ambiguous numeric dates.
- Unsupported recurrence and partially understood dates/times are rejected.
- Named timezones use the current Emacs timezone's fixed UTC offset at the
  reference date.  Conversion across a DST offset change is not supported.

~org-natural-dates-duckling-stop~ releases the helper process.  Disabling the
global mode removes its advice and restores the previous parser.

** Installation

*** MELPA (coming soon)

#+begin_src emacs-lisp
M-x package-install RET org-natural-dates RET
#+end_src

*** use-package with straight.el

#+begin_src emacs-lisp
(use-package org-natural-dates
  :straight (org-natural-dates :type git :host github :repo "ewilderj/org-natural-dates")
  :after org
  :bind (:map org-mode-map
         ("C-c C-s" . org-natural-dates-schedule)
         ("C-c C-d" . org-natural-dates-deadline)
         :map org-agenda-mode-map
         ("C-c C-s" . org-natural-dates-agenda-schedule)
         ("C-c C-d" . org-natural-dates-agenda-deadline))
  :config
  (add-hook 'org-capture-before-finalize-hook #'org-natural-dates-capture-finalize-hook))
#+end_src

*** Manual

Clone and add to your =load-path=:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/org-natural-dates")
(require 'org-natural-dates)
#+end_src

** Configuration

Bind the commands over the standard Org scheduling keys:

#+begin_src emacs-lisp
;; In org-mode buffers
(with-eval-after-load 'org
  (define-key org-mode-map (kbd "C-c C-s") #'org-natural-dates-schedule)
  (define-key org-mode-map (kbd "C-c C-d") #'org-natural-dates-deadline))

;; In the Org Agenda
(with-eval-after-load 'org-agenda
  (define-key org-agenda-mode-map (kbd "C-c C-s") #'org-natural-dates-agenda-schedule)
  (define-key org-agenda-mode-map (kbd "C-c C-d") #'org-natural-dates-agenda-deadline))
#+end_src

With a prefix argument (=C-u C-c C-s=), the commands fall back to standard =org-schedule= / =org-deadline= behaviour (calendar picker, date removal, etc.).

** Supported input formats

- *Relative dates:* =tomorrow=, =today=, =yesterday=, =in 3 days=
- *Named days:* =Monday=, =next Tuesday=, =last Wednesday=, =Fri=
- *Times:* =at 5pm=, =at 19:00=, =@ 9=
- *Recurrences:* =every day=, =every 2 weeks=, =every Friday=, =every other month=
- *Ordinals:* =on the 15th of every month=, =on the 2nd of every month=
- *Combined:* =every Monday at 10am=, =tomorrow at 3pm=
- *Deadline keywords:* =due Friday=, =by tomorrow=, =deadline in 3 days=

** Org Capture integration

Add the finalize hook to parse natural dates from capture headlines automatically:

#+begin_src emacs-lisp
(add-hook 'org-capture-before-finalize-hook #'org-natural-dates-capture-finalize-hook)
#+end_src

With this, typing =* TODO Brush teeth every day at 5pm= during capture (=C-c c=) will, on finalize (=C-c C-c=), clean the headline to =* TODO Brush teeth= and insert the correct =SCHEDULED:= timestamp.

Deadlines are auto-detected via keywords: =due Friday=, =deadline in 3 days=, =by tomorrow=.
